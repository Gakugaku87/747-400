### 重いもの（型ごと）

- **D（時間）**：XTLua の `SIM_PERIOD` は定数 0.02 で、モジュールは X-Plane のフレームを待たずに回り続ける。X-Plane が止まっている間も、AFDS・A/T・トリム・EEC・始動・autobrake が凍った入力で積分を続ける。利用者の PC の 4 回の跳びの原因。時間加速では則が実時間のまま。
- **E（過渡）**：F/D だけの間の指令の巻き上がりと CMD、STAR の途中の ARRIVALS の選び直し、着陸復行の CONFIG GEAR、tank to engine の後のメッセージ、driftdown でレバーを閉じると HOLD、リバリーの読み込み、軽い機体の FLCH の小さな降下、捕捉での速さの行き過ぎ。
- **A（端）**：実際の気象の上昇の揺れ、P&W の最大 EPR、全発停止の油圧、ADC・IRU の片側の故障、静圧孔の故障での最大速度、T/O の片発の混合。
- **B（行き止まり）**：ばね戻りのスイッチ（OUTFLOW の CLOSE が効かない）、パーキング・ブレーキが実機の手順で入らない、auto start が機体を止めて中止する。
- **C（黙って効かない）**：離陸の抑止が一度も武装しない、滑走路の点が無い進入（7,349 本）、(INTC) の次の IF、>ENG n SHUTDOWN の表の読み違い、高度到達の弧、遷移レベルが FL180 固定、SAT R の灯。

### 時間の扱い（担当 4。担当 1 の AFDS-1・AFDS-2、担当 2 の AT-5 と同じものはここにまとめる）

根本の原因は 1 つで、親が本家 XTLua のソース（`lua_helpers.cpp`・`xlua.cpp`）と同梱のバイナリで確かめた。

- `SIM_PERIOD` は定数 0.02（フレームの長さでも実時間でもない）。
- `before_physics`・`after_physics` は、XTLua のワーカースレッドが X-Plane のフレームを待たずに約 20 ms ごとに呼ぶ（この PC の記録では 1 周 21.1 ms：Lua の時間は sim の時間の 94.6 %）。dataref の受け渡しは X-Plane のフレームごと。
- X-Plane の主スレッドが止まる（長いフレーム）と、ワーカーは凍った入力のまま回り続け、積分・タイマーが止まった秒数ぶん進む。明けの 1 フレームで全部が一度に出る。
- `AFDS_DT_MAX`・`SRM_DT_MAX`・`EEC_DT_MAX`（0.05）は、`SIM_PERIOD` がいつも 0.02 なので一度も効いていない。
- 一時停止の間は呼ばれない（燃料・APU のコメント「SIM_PERIOD は一時停止でも進む」は誤り。2026-11-11 の FUEL-1 の再現はモックの上だった。直しそのものは止まりに対して正しい向き）。

## 直す案

直す案ごとに、根拠・推定かどうか・影響・HEAD で落ちる回帰試験・X-Plane のシナリオを書く。「既存の調整を変える案」は B に分けた。

### A. 直すことを勧めるもの（資料か実装の誤りがはっきりしていて、既存の調整を変えない）

**案 1　X-Plane が止まっている間は、モジュールを回さない**（D-1＝AFDS-1、D-2、D-3、D-4、D-8、D-5）
- 中身：4 つの `plugins/*/init.lua` の `do_callout` で、X-Plane の時計（`sim/time/total_running_time_sec`）が 5 tick（0.1 秒）続けて動いていなければ、`before_physics`・`after_physics` を呼ばない（一時停止と同じ扱い）。動いたら次の tick から戻る。`afds_dt` などの効いていない上限と、そのコメントも直す。
- 根拠：資料なし（シムの都合）。推定ではなく実装の誤り（XTLua のワーカーは X-Plane のフレームを待たない：本家のソースで確認）。
- 影響：全モジュール。ふつうの飛行（20 fps 以上）では何も変わらない。10 fps 未満では、1 フレームの後ろの方の tick を飛ばす（Lua の時間が遅くなる向き。X-Plane の時間も 19.9 fps の下では遅くなる）。止まりの影響は最大 0.1 秒ぶんになる。
- 回帰試験（HEAD で落ちる）：モック（`tests/lib/xtlua.lua`。本物の `init.lua` を読んでいる）に「X-Plane の時計と値を止めたままの tick」を足す。10 秒ぶんの tick の後、`pitch_cmd`・`lever_cmd`・`elevator_trim` が動かない、A/T が THR のまま、autostart が中止しない、autobrake の指令が変わらない。`rt:frame(2)` の 2 件はこれに替える。
- X-Plane：FlyWithLua の主スレッドを止めるコマンド（今回の確かめで作った `B747_stall_test.lua` をキットに入れる）で、(1) VNAV SPD の加速中に 10 秒：`pitch_cmd` の段 0.1° 以内・その後 30 秒 0.9〜1.1 g、(2) FLCH の 1 秒後に 10 秒：A/T が THR のまま、(3) s114 の FLARE の RA 25 ft で 0.6 秒：浮かない、(4) autostart の N2 35 % で 30 秒：始動が続く。

**案 3　A/P を入れた時に、ピッチの指令を今の姿勢に同期する**（AFDS-5）
- 中身：CMD の engage の瞬間に、ピッチの則の指令（`s.cmd`）を今の姿勢に置き直す。F/D だけの間のバーの動きは変えない（F/D だけの間の巻き上がりそのものを抑える案は、手動の F/D の見え方が変わるので、ここには入れない）。
- 根拠：ATA22 p.332（22-12 p.6）：A/P が外れている間、ピッチ姿勢の積分器は姿勢に同期する。engage の後に指令の入力を受け始める。推定ではない。
- 影響：A/P を入れる時だけ。入れた直後の動きが、今の姿勢からモードの目標へ則の速さで移る形になる。「次にやること」16 の件。
- 回帰試験：グルーの試験に、F/D のまま V/S +1,000 で 30 秒（姿勢は動かさない）→ CMD の次のフレームの `pitch_cmd` が姿勢の 0.5° 以内（HEAD は 8° 上）。
- X-Plane：今回の `v_fd_windup`（CMD の後 20 秒の荷重倍数 0.9〜1.1。HEAD は 1.83 g）。離陸（s109・s141：回転の後に A/P を入れる）も回して、変わりを見る。

**案 4　A/T：手の入力で HOLD になるのは FLCH だけにする。止まったエンジンのレバーは平均に入れない**（AT-7）
- 中身：(1) VNAV の THR（driftdown・巡航降下・早期降下）では、レバーが指令から 8° 離れても HOLD にしない（手を離せば指令に戻る）。(2) 手の入力の判定に使うレバーは、運転中のエンジンのもの（今は 4 本の平均）。
- 根拠：(1) ATA34_2 p.648（34-61 p.222）「Pilot Override Logic」。(2) は資料なし（推定）。
- 影響：VNAV の THR の間に手でレバーを動かしたとき。driftdown で止まったエンジンのレバーを閉じても THR のまま。
- 回帰試験：`at_model_test` に、VNAV の THR（driftdown、指令 0.70）で 1 本を閉じる → THR のまま（HEAD は HOLD）。FLCH の THR は今までどおり HOLD。
- X-Plane：s157（driftdown）で THR の後、`throttle_ratio[1]` を 0 に：`FMA/autothrottle_mode` が 4 のまま。

**案 5　滑走路の点が無い進入：滑走路を進入の名前から補い、E/D は MAP にする**（FMC-1）
- 中身：`approach_legs` が RW の点を見つけないとき、滑走路を進入の識別子から取る（ARRIVALS のページの `star_serves` は既にそうしている）。E/D は、RW の脚が無ければ MAP（進入復行の脚にはしない）。ILS の同調もこの滑走路で引く。
- 根拠：FCOM p.1258（E/D は RW の点の 50 ft 上、VOR 進入は MAP）、p.1261、p.1306–1307。LOC・LDA・RNAV の MAP を E/D にするのは VOR 進入の記述からの類推（推定と明記）。
- 影響：7,349 本の進入（RJAA の LOC16R・VOR16R、RJTT の LDA、YSSY・VTBS の RNAV など）。T/D の位置、STAR の滑走路別の部分、ILS の同調が変わる。
- 回帰試験：試験用の航法データ（ZZAA）に、MAP で終わる進入を足す。E/D が MAP、STAR に滑走路別の脚が入る、`dest_ils` が LOC を返す（HEAD はどれも落ちる）。
- X-Plane：RJTT で AKSE1B＋LDA22-W（LEGS に SALLY〜BACON、VNAV 3/3 の E/D、NAV RADIO の ILS の行）。RJAA の LOC16R の T/D が ILS16R Y の ±10 NM。

**案 6　飛んでいる手続きを選び直したとき、現用の脚までを残す**（FMC-2）
- 中身：`set_arrival`・`set_dest` で、現用の脚が外す手続き（STAR・進入）の中にあるとき、現用の脚までは残し、その後ろだけを作り直す。
- 根拠：FMSPG p.79（3.2-19：DEST の変更で、現用の脚がその手続きの一部なら、現用の脚の後ろだけが消える）。ARRIVALS の選び直しは同じ扱いにする（資料なし：推定）。実機の INTC> の prompt（FCOM p.1403–1405）は作っていない。
- 影響：STAR・進入の途中での滑走路の変更、ダイバート。2026-11-12 の ARRIVALS の直しと同じ場面（利用者の WSSS の飛行）。
- 回帰試験：`arr_change_test` に、STAR の 2 点を通過した後の進入の選び直し（現用の点が変わらない、通過済みの点が戻らない）と、DEST の入れ直し（現用の脚が残る）。HEAD は落ちる。
- X-Plane：今回の `v_fmc_arr_mid_wsss`（EXEC の後も LEGS の 1 行目が BOKIP、`lnav/mode` 1、XTK 1 NM 以内）。

**案 7　(INTC) の次が IF のとき、IF の先の脚のコースに会合する**（FMC-3）
- 中身：`path_model` の会合の相手に「IF とその次の CF・TF」を足す。
- 根拠：FCOM p.1249（(INTC) は次の点へのコースへの会合）。推定ではない。
- 影響：進入 835 本・SID 469 本（RJAA ILS16R Y、RJBB ILS24R Y、EDDF、VIDP など）。APP を押さずに LNAV で最終進入コースへ入る場面。
- 回帰試験：試験用のデータに VI → IF → CF の並びを足し、LNAV のモデルで (INTC) が順送りされて CF のコースに乗る（HEAD は 600 秒たっても (INTC) のまま）。
- X-Plane：RJAA、4,000 ft、LAKES の手前から ILS16R Y を LNAV だけで：3 分以内に (INTC) が順送りされ、KONAN→TENAG の上で XTK 0.5 NM 以内。

**案 8　RTE の RUNWAY の変更で SID の脚を入れ直す。合わない組にはメッセージ**（FMC-4）
- 中身：`set_runway` が SID の滑走路別の部分を入れ直す。SID を先に選んだ後の滑走路も同じ。SID がその滑走路に無ければ SID を外して RUNWAY N/A FOR SID（今は黙って脚が 0 本）。
- 根拠：FCOM p.1301、FMSPG p.90・p.79（RTE の RUNWAY は DEPARTURES と同じ欄）。RTE 2L で SID の脚が入れ替わることの明文は無い（同じ欄という記述からの読み）。
- 影響：出発前の滑走路の変更。
- 回帰試験：ZZAA で 16R＋ZULU1 の後に RTE 2L へ 34L：脚が `(600) (INTC) ZZV`（HEAD は `ZA001 ZZV`）。34L の後に YANKE1：メッセージ。
- X-Plane：RJAA の地上で、DEPARTURES で 16R と SID、RTE 2L に 34L：LEGS の頭の 3 行が DEPARTURES で 34L を選んだときと同じ。

**案 9　手続きの点はその空港のターミナルの点から、LOC は進入の推奨の施設から引く**（FMC-5、FMC-6）
- 中身：`navdb.point` に空港を渡し、手続きの点はその空港のターミナルの点を先に、NDB・LOC は空港に近いものを取る。ILS の同調は進入の脚の推奨の施設の識別子で引く。
- 根拠：CIFP（ARINC 424）の欄の意味、FCOM p.1306（選んだ進入の ILS を同調）。推定ではない。
- 影響：21 手続き（RJTT SULP1D など）、NDB 80 本、LOC 45 本（EDDF・KDTW・KORD・ZSPD など）。
- 回帰試験：試験用のデータに、同じ識別子のエンルートの点とターミナルの点、LOC が 2 つある滑走路を足す。
- X-Plane：RJTT の SULP1D で、LEGS の D097V の次の行の距離が 40 NM 未満。

**案 10　FMC の小さい直し**（FMC-8、FMC-9、FMC-10 の一部）
- RTE HOLD の SPD/TGT ALT は CRZ ALT と同じ高度を受ける（ブロックは不可）：FMSPG p.127。
- 有効な経路の先にある点を LEGS の 1L・HOLD AT に入れたら、SELECT DESIRED WPT を出さずにその点を使う：FCOM p.1249。
- 周回進入の名前（VORA など）をそのまま出す。SPD REST は速度と `/` と有効な高度だけを受ける（FMSPG p.114）。CLB・DES の 1R の DELETE（FMSPG p.114）。
- どれも HEAD で落ちる試験を足せる（担当のスクリプトの形）。X-Plane は CDU の行を読むだけ。

### B. 既存の調整を変える案（理由と資料）

**案 2　AFDS・A/T・SRM・EEC の則の時間を、X-Plane の時計の差にする**（D-7＝AFDS-2、AT-5）
- 変えるもの：`afds_dt()`、SRM、EEC の推力の制御の dt（今は定数 0.02 ＝ 実時間）。内側の PID・燃料・APU は既にこの形。

- X-Plane：今回の `v_accel_capture_x2`・`_x4`（行き過ぎ 50 ft 以内）、`v_at_accel_*`。

**案 B2　EEC の全開の定格とレバーの線：P&W は最大 EPR を離陸・G/A の定格のままにする。CF6 は CLIMB の位置で線を分ける**（AT-1、AT-2、AT-8）
