# 試験（TESTING）

作り直しの各項目は、次の 4 段で確かめる。

1. **構文チェック**：LuaJIT（`luajit -bl`）、または Lua 5.1 の `luac -p`。
2. **回帰試験**（`tests/`）：LuaJIT で X-Plane なしに回す。旧フォークの試験の仕組みを流用し、系統ごとに作る（§3）。
3. **X-Plane での試験**：飛行試験キット（§4）と Web API で回し、`Log.txt` のエラーも確認する。
4. **利用者の目視確認**：自分で確かめられなかった点だけを回す。

## 1. 旧フォークの試験（`tests_old/`、参照専用）

### 1.1 扱い

- `tests_old/` は `archive/old-master` の `tests/` と同じ中身（85 ファイル）。`ap_pitch_loop_test.lua` だけ改行コードが違う。
- `.git/info/exclude` で git の管理から外してある。旧フォークのコード向けなので、そのまま通す必要はない。
- 中身は FlyWithLua のスクリプトではなく、**LuaJIT で X-Plane なしに回す回帰試験**。本番の Lua をモックの上で読み込む。
  - 試験 76 本、閉ループのモデル 4 本（`approach_model.lua`、`climb_model.lua`、`roll_model.lua`、`mcp_alt_dial_model.lua`）、記録データ 4 本（`data/*.csv`）。
- 回し方は、リポジトリの直下から `luajit tests/<名前>_test.lua` を 1 本ずつ（1 本に 1 つのインタプリタ）。`lua5.1` でも動く（README）。

### 1.2 仕組み（4 つの手法）

| 手法 | やり方 | 例 |
|---|---|---|
| a. 純粋なモジュール | 本番のロジックを、表を返すモジュールに分けておく。試験は `dofile` で読み、入力の表を渡して出力を確かめる | `takeoff_profile_test.lua`（`B747.70.xt.autopilot.takeoff.lua` の `new` / `update`） |
| b. XTLua の名前空間の再現 | 本物の `plugins/xtlua_keysystems/init.lua` を `loadfile` と `setfenv` で読み、`create_namespace()` で XTLua と同じ名前空間を作る。本番ソースから目印（関数名など）の間を切り出し、`loadstring` と `setfenv(fn, ns)` でその中で実行する。dataref は名前空間の変数として与える（`ns.simDR_x = 値`） | `xtlua_route_constraints_test.lua` |
| c. ソースの静的検査 | 本番の Lua を文字列で読み、規則を検査する：xt スクリプトが `deferred_dataref` で使う `laminar/` の名前を init スクリプトが作っているか（`deferred_command`・`find_command` で使うコマンドも：XTLua ではコマンドも init で作る。モックはどんな名前のコマンドも通すので、5-2 段 5c で足した）、名前空間で束ねていない dataref 名に書いていないか、必要な dataref を毎フレーム読んでいるか（warm read） | `hydraulics_dataref_binding_test.lua`、`xtlua_warm_reads_test.lua` |
| d. 閉ループのモデル | 点質量の 747 と、記録に合わせた X-Plane の姿勢応答のモデルで本番の制御則を回す。フレームレート（15・20・34 fps）を変えても結果が変わらないことを確かめる | `approach_model.lua`、`climb_model.lua`、`afds_speed_on_pitch_test.lua` |

- **モック**：
  - dataref は名前空間の変数、コマンドは関数の呼び出しで置き換える。
  - タイマー（`run_at_interval` など）、`print`、境界の関数（`getFMSData` など）は、試験側で差し替える。
- **判定**：`check` / `equal` / `near(実際, 期待, 許容)` で数える。失敗を集めて最後に `error` を出し、成功すれば件数を表示する。
- **XTLua の落とし穴**（旧フォークで分かったこと。新しい試験でも押さえる）：
  - スクリプトのモジュール内で、dataref の最初の読みは 0 になる → 要る dataref は毎フレーム読む。
  - xt スクリプトの `deferred_dataref` は `find_dataref` と同じ → init スクリプトで作っていないと存在しない。
  - メタテーブルの無い global テーブルの、無い添字を読むとスタックが溢れる。
  - チャンクをまたいで local は見えない。XTLua 独自の `dofile` の戻り値。1 回だけのコマンドには phase 2 が来ない。
  - Web API で XTLua の double 型 dataref に小数を書くと HTTP 400 になる（incompatible_data。float の配列の要素も、配列ごとも同じ。整数は書ける：2026-11-02）。走行中に小数の値を試すときは、百分率などの整数で書いてコードで割るか、FlyWithLua で書く。
  - `run_after_time` のタイマーは、関数を呼んだ後で止まる（XTLua の `xptimers.cpp`：繰り返しの無いタイマーは、関数の後で次の時刻を消す）。関数の中で自分を `run_after_time` し直しても、二度と走らない。繰り返すなら `run_at_interval`（初めの遅れが別なら `run_timer(f, 遅れ, 間隔)`）で回し、終わりに自分で `stop_timer`（関数の中でも効く）。X-Plane なしの試験（`tests/lib/xtlua.lua`）も 2026-11-01 から同じにした。前は呼ぶ前に外していたので予約し直しが効いて見え、FMS の空中開始の待ち（F/D と CMD L の押し直し）が X-Plane では 1 回しか走らないのを見逃した。
  - X-Plane の dataref に、前に書いたのと同じ値を書いても X-Plane には渡らない。X-Plane が値を変えた後は、そのモジュールが読み直すまで直らない（XTLua の xpmtdatarefs.cpp：書くとキャッシュと比べ、違うときだけ次のフレームで 1 回渡す。読むと次のフレームで X-Plane から読み直す。2026-10-23 に、Web API で cross tie を書き換えると、毎フレーム書いている電源のグルーが元に戻さないことを確かめた）→ X-Plane の dataref は毎フレーム読んで、違うときだけ書く。X-Plane なしの試験（`tests/lib/xtlua.lua`）はこれを再現しない。

## 2. 流用するもの・しないもの

- **流用する**：
  - 1 本に 1 つのインタプリタで回す形、判定の道具（`check` / `equal` / `near`、失敗を集めて最後に出す）
  - XTLua の名前空間の再現（本物の `init.lua` を読む方式）
  - 静的検査（init で作られているか、束ねていない名前への書き込み、warm read、global テーブルのメタテーブル）
  - CSV の読み込みと補間、閉ループのモデルの骨組み（フレームレートを変えて回す形）
  - README の X-Plane での確認シナリオ（§1.4）のうち、資料で裏付けが取れるもの
- **流用しない**：
  - 旧コードの関数名や目印に頼った切り出し。新しいコードでは、試したいロジックを純粋なモジュールに分け、`dofile` で読む形を基本にする。
  - 旧コードの調整値。記録に合わせただけのモデルの定数も含む。
- **期待値**：
  - 旧試験の期待値は、資料（FCOM・FCTM・整備マニュアル）で裏付けが取れたものだけを新しい試験に移す。移した値には、コメントで出典（`FCOM p.801 (6.20.7)` の形）を付ける。
  - 裏付けの無い値は移さない。どうしても要るときは「推定」と書く。

## 3. 新しい回帰試験（`tests/`、git 管理）

- 回し方（リポジトリの直下から。LuaJIT の場所は §6）：
  - `bash tests/run.sh`：`tests/**/*_test.lua` を 1 本ずつ LuaJIT で回す。
    - 終わりから 2 行目の `checks N` は、合格した試験の確認の数の合計（各試験の「N checks passed」の和。2026-11-12）。同じコミットなら、どの PC でも `checks` と `passed` は同じ数になる（下の「X-Plane の無い所で回すとき」）。
  - `bash tests/syntax_check.sh`：機体の Lua（git 管理のもの）と試験の構文チェック（`luajit -bl`）。
  - `luajit tests/tools/same_behaviour.lua <入力> [git の版]`：挙動を変えない変更の確認（下）。
  - `luajit tests/tools/mutate.lua <指定のファイル> [-k] [-j] [-m <フォルダー>]`：変異の試験（2026-11-12）。あるファイルを 1 か所ずつ壊し、決めた試験を当てて、落ちなかった壊し方（試験の穴）を出す。指定は Lua の表を返すファイル：壊すファイル `file`、回す試験 `tests`、壊し方 `mutations`（`{元の文字列, 置き換え}`。同じ文字列が何か所もあれば `n` で何番目か、`"all"` で全部。壊し方ごとに別の `file` と `name` も書ける）、ほかに試験が読むファイル `files`、1 本の制限時間 `timeout`。作業ツリーは変えない：試験の要るファイル（`plugins` と `tests` の、git が挙げるバイナリー以外のファイルと `INTERFACES.tsv`）を TEMP のフォルダー（`-m` で場所を指定）に写し、そこで壊して回す（`XPLANE_ROOT` は自動で元の X-Plane のフォルダー）。まず壊さずに全部の試験が通ることを確かめ、壊し方ごとに試験を順に回して、最初に落ちた試験を出す。終わりに、落ちなかった壊し方（NOT CAUGHT）を元の文字列と置き換えつきで並べる。落ちなかったもの・壊せなかったもの（文字列が無い、複数ある）があれば終了コード 1。壊すと終わらなくなる繰り返しに備えて、試験は JIT を切って制限時間つきで回す（壊さないときの 10 倍、最低 60 秒。時間切れは「落ちた」に数える。`-j` で JIT のまま・制限なし）。例：`tests/tools/mutations/spd_way.lua`（速度の則の「ほぼ水平」：則・VNAV のモデル・グルーの 17 通りが全部落ちる。約 16 秒）。レビューで直した所の試験の確かめにも使う。前の版との出力の比べは `same_behaviour.lua`。
  - `luajit tests/tools/panel_names.lua [acf]`：acf のパネルが使う laminar/ の名前のうち、INTERFACES.tsv に無いものを、INTERFACES.tsv の行の形で出す。カスタム acf のパネルを変えたら回して、出た行を INTERFACES.tsv に足す（名前の順）。
  - `luajit tests/tools/pitch_sysid.lua <session.csv> <t0> <t1> [遅れ] [FMA]`：飛行試験の記録から、X-Plane の 747 のピッチの動き（ピッチの角加速度と迎え角の変化率を、ピッチの角速度・迎え角・昇降舵・トリムで）を最小二乗で当てはめる。`luajit tests/tools/attitude_loop_sim.lua`：その模型に A/P の姿勢のループ（PID、昇降舵の指令の速さ、自動トリム）と高度の則を載せて比べる（notes/ATA-22.md §20）。`luajit tests/tools/inner_loop_150kt.lua`：150 kt・フラップ 30 の模型（s114 の 3 回目から当てはめた）で、内側のループのゲインの速度による倍率（姿勢の変化率と積分の乗数）を、1° の段の揺れと FLARE の傾斜での遅れで比べる（§26）。`luajit tests/tools/lat_sysid.lua <session.csv> <t0> <t1> [遅れ]`：記録 v6 から、X-Plane の 747 の横・方向の動き（横滑り角の変化率、ロールとヨーの角加速度）を、横滑り角・ロールとヨーの角速度・バンク・補助翼・方向舵の入力で当てはめる（6-3 段 4d：§29）。150 kt・フラップ 30 の模型は `tests/tools/lat_model_150kt.lua`（s115 から）。`luajit tests/tools/roll_loop_150kt.lua`：その模型で A/P の内側のロールのループ（比例・積分・ロールとヨーの角速度、サーボの速さ）を、旋回の入りの行き過ぎと、翼を水平に保つときの方向舵の段への傾きで比べる（§30）。`luajit tests/tools/align_sim.lua [横風 kt] [片発の方向舵] [開始 ft] [multi ft] [横の m]`：その模型に、ロールの則（LOC と runway align）と内側のロールのループを載せて、3° の経路で 5 ft まで飛ばし、crab・横滑り・バンク・方向舵・補助翼・中心線からの距離を出す（§29、§31）。

### 4.1 方針

- **Web API が中心**。X-Plane 12.4 以降の v3 で、dataref の読み書き、コマンドの実行、フライトの開始（`POST /flight`）を使う。スクリーンショットは X-Plane のスクリーンショットのコマンドを Web API から実行し、出てきた画像を取る。

- XTLua は、モジュールの毎フレームの呼び出し（`before_physics`・`after_physics` など）で Lua の実行時エラーが出ると、そのプラグイン（例：`xtlua_keysystems` の FMC・AFDS・計器・空調・照明など）の全モジュールを止める（XTLua の `xlua.cpp`：`active=false` の後は眠るだけ）。エラーの文はコンソール（printf）にしか出ず、`Log.txt` には何も残らない。A/P・FMC・CDU が止まったまま X-Plane は飛び続け、CPU も使わない（2026-11-02：`s150` の G/A の 2 フレーム後に F/D の指令が止まり、14 項目が不合格）。そこで、4 つの `plugins/*/init.lua`（同じ中身）の `do_callout` は、エラーの文と traceback を X-Plane のフォルダーの `Output/B747_xtlua_errors.txt` に足してから、エラーを XTLua に返す（動きは前と同じ。回帰試験の作業フォルダーには `Output/` が無いので書かない）。`run_scenario.ps1` は、その回に新しい行が出たらその場で不合格にしてシナリオを止め、記録のフォルダーの `xtlua_errors.txt` に写す。タイマーとコマンドの処理の中のエラーは、XTLua が C から直に呼ぶので書かれない。4 つの `init.lua` は同じ中身に保つ。
- 画面が止まる報告のための記録（2026-11-05、利用者「この機体だけ、何かの操作で一時的に画面が固まることがある」）：X-Plane のフォルダーの `Output/B747_hitches.txt`。FMS ブリッジ（`plugins/b747_fms_bridge/src/hitch_log.c`）は、描画のスレッドのフレームが前から 0.25 秒以上（シムの時間が進んでいて 20 秒未満）あいたら、時刻（ミリ秒まで）と、その間のブリッジの仕事（X-Plane の FMS への経路の読み込みと点の数、遅いときのフォルダーの走査）を書く。XTLua の 8 つの `init.lua`（スレッド側の `plugins/*/init.lua` 4 つと、描画のスレッドで動く `plugins/*/init/init.lua` 4 つ。それぞれ同じ中身）は、呼び出し・タイマーの関数・コマンドの処理が 0.2 秒を超えたら、モジュールのファイル、何か（呼び出しの名前、タイマーの関数のファイルと行、コマンドの名前）と時間を書く（関数を作るときに時間を測る関数で包む。`os.clock` は Windows では経過時間）。1 回の読み込みでブリッジ 300 行、モジュールごと 60 行まで。`tests/static/hitch_log_test.lua`。

- X-Plane の Network 設定で「Disable Incoming Traffic」が入っていると、すべて 403 になる。
- XTLua の double 型 dataref に小数を書くと 400 になる（旧フォーク）。キットでは書き方を工夫するか、FlyWithLua 側で書く。2026-10-24 に X-Plane 12.4.4 でも確かめた（`incompatible_data`。整数と 1.0 は書ける。X-Plane 自身の float の dataref は小数も書ける）。シナリオではノブの dataref などに整数だけを書く（`s16` の PASS TEMP は W と C）。
