# overhaul 全体のレビュー（2026-11-05、Fable）

利用者の依頼で、overhaul（本家 041c9ffa から 840 コミット、1,184 ファイル）を、Fable（claude-fable-5-1）のレビュー担当 10 体で分野ごとに読んでもらった。ファイルは読むだけで、何も変えていない。担当の英語の報告は [REVIEW_2026-11-05_findings.md](REVIEW_2026-11-05_findings.md)（場所・根拠・直し方つき）。

- 担当：1 FMC の航法、2 FMC の性能・VNAV、3 FMC の CDU・データリンク、4 AFDS・A/T、5 表示（PFD・ND・EICAS、ND の線）、6 電源・警報・通信・火災・酸素・照明、7 油圧・空圧・空調と与圧・防氷、8 エンジン・EEC・燃料・APU、9 操縦系統・脚・航法センサー、10 FMS ブリッジ（C）・XTLua の読み込み部・試験の仕組み。
- 途中で Fable の週の上限に当たって一時停止し、16 時の再開から最後まで回した。
- 印：【確認済み】は私（Opus）もコードを読むか実行して確かめたもの。【担当】は担当の確認だけ。

## 全体の評価

作り直した部分（純粋なモデルと、dataref をつなぐグルー）は構造がよく、XTLua の落とし穴（毎フレームの読み、名前空間の表、タイマー）にも気を配ってある。試験も中身を本当に確かめている（全 212 本合格）。各担当が照らした FCOM・整備マニュアルのページは、ほとんどがコードと一致した。

重い不具合は、主に元の機体から引き継いだ古いコードにある。今日入れた便利機能が、そのうち 1 つを踏みやすくしていた（下の 1-1）。

## 1. プラグインが丸ごと止まる不具合（最優先）

XTLua は、Lua のエラーが 1 つ出ると、そのプラグインの全モジュールを止める（ログにも出ない）。

1. **TAKEOFF REF の CG を、重量より先に入れると止まる**【確認済み】
   - 起きること：GR WT・ZFW を入れる前に TAKEOFF REF の CG（R4）を入れると、`calc_stab_trim` が「***.*」の文字列に掛け算をして Lua エラーになる（`B744.fms.pages.lua:1529`、`B747.68.xt.fms.lua:486`）。
   - 止まるもの：`xtlua_keysystems`（FMC・AFDS・表示・空調・照明など）。
   - 範囲：CG を打ち込む場合は前からあった。今日の便利機能（最初から入）で、空のスクラッチパッドのまま R4 を押すだけで起きるようになった。
   - 試験に無かった理由：試験はいつも ZFW を先に入れていた。
2. ~~**P&W の機体で、推力制限を CRZ にすると止まる**~~ → **誤報**（同じ日の直す作業で分かった）
   - 担当の見立て：CRZ の EPR の表（重量 → 高度 → EPR）を、表を引く関数が一段ずれて読み、Lua エラーになる。担当は素の表で再現していた。
   - 実際：XTLua では、グローバルに置いた表は名前空間に包まれ、`pairs()` がまず「values」「functions」の表を返す。元の関数は、その一段を飛ばす書き方で正しく動く。
   - 確かめたこと：本物の `init.lua` を読む試験（`tests/eec/eec_module_test.lua`）で、P&W・GE・RR とも CRZ で Lua エラーは出ない。
   - 結果：コードは変えず、CRZ を通る試験だけ足した。私の「確認済み」も、この包みを見落とした誤りだった。
3. **PAX/CARGO ページに小数の人数（例：30.5）を入れると、XTLua が固まり続ける**【担当が再現】
   - `repeat … until (x == 0)` が 0 を飛び越えて終わらない（`B744.fms.pages.lua:1568-1606`）。元の機体のコード。
4. **ND のウェイポイントのファイルが無いと止まる**【担当】
   - `io.open` の直後に nil を確かめていない（`B747.61.xt.nd.lua:1212-1215`）。普通の環境では起きない。
5. 潜在：`fmsModules.setData` に、表に無い名前が来ると止まる。今は呼ぶ所が無い【担当】。

## 2. 画面が固まる件の候補

この PC では再現しなかった（記録つきの版で、C&D からの始動、経路を入れての離陸、ボタン 40 回、どれも 0.2 秒を超えた機体の処理は無し）。

一方、起動直後の ND の処理 0.97 秒と同じ時刻に、描画も 0.50 秒止まっていた。XTLua の処理が遅れると、描画も止まりうる。候補は次のとおり。どれが効いているかは、利用者の PC の `Output/B747_hitches.txt` で決める。

- **POS INIT のページが、毎フレーム CDU ごとにファイルを開いて読む**【確認済み】
  - 中身：前回の位置のファイル `<livery>/B747-400_lastpos.dat` を読み直している（`B744.fms.pages.posinit.lua:97` → `B747.68.xt.fms.lua:5713-5724`）。
  - 症状との関係：C&D からの準備中に開いておくページ。元の機体のコード。
  - 直し方：読み込み時かページを開いたときに 1 回読む。
- **空港の手順のファイルと、航法データの格子を、最初の 1 回にまとめて作る**【担当の見立て】
  - CIFP：ORIGIN・DEST の入力、DEP/ARR ページ、REF NAV DATA で、その空港のファイルを同じフレームの中で全部解読する（`B747.68.navdb.lua:449-497`）。Navigraph の大きな空港は約 400 KB。
  - 格子：磁気偏差と近くの無線局の格子を、最初の LEGS の表示などで、航法データ全体（約 29 万行）から一度に作る（同 533-582）。
  - 症状との関係：遅い PC では数十〜数百ミリ秒になりうる。CDU の入力の直後に起きるので、症状と合う。
- **経路を変えるたびに、1 秒後、X-Plane 自身の FMS へ経路を読み込み直す**【担当の見立て】
  - 中身：全地点を 1 つずつ消してから読み込む処理を、描画のスレッドで行う（`b747_fms_bridge.c:327-346`）。
  - 確かめ方：記録の「X-Plane FMS plan load」の時間で分かる。
- **ND の経路の線の描画が、画面外の区間まで毎フレーム計算する**【担当】
  - 中身：区間を最大 64 に分けて、見えるかどうかを見る前に投影する。1 フレームに 2 回、左右とも（`nd_line.c:380-461`）。
  - 重さ：短い範囲と長い経路で、毎フレーム数千回の三角関数の計算になる。固まるより、常にかかる重さ。
- **毎フレームの重い習慣**【確認済み】
  - 燃料・EEC・ND・FDR の各モジュールが、毎フレーム Lua のゴミ集めをまるごと回す。燃料と EEC は同じ Lua の中なので、プラグイン全体のメモリを毎フレーム 2 回掃除している。
  - FMC が、毎フレーム全データを JSON にして書き出す（元の機体のコード）。
- **起動直後の ND の 0.97 秒**【担当の見立て】
  - Lua の処理を測るとそこまでかからない。XTLua 自身が最初に航法施設を探す処理で、止まったと見られる。確かめるには、ND の処理を段ごとに測る必要がある。

## 3. 動きの誤り（中）

- **A/T の状態が、次のフライトに持ち越される**【確認済み】
  - 中身：フライト開始で作り直すのは AFDS だけで、A/T のモデルや VNAV ALT の保持などは残る（`B747.70.xt.autopilot.lua:1538-1542`）。
  - 症状：前のフライトの終わりに A/T が入っていると、新しいフライトで AUTOTHROT DISC が出る。
- **進入中、電波高度 400 ft 未満で、A/T の SPD・THR スイッチが効かない**【担当】
  - FCOM p.641-642 では「離陸後 400 ft から着陸まで」有効（`B747.70.at_model.lua:236-247`）。試験はこの誤りを正としている。
- **DES NOW の予測が、CRZ ALT より上になり、到着が早く出る**【担当が実行して確認】
  - 例：FL350 で T/D の 130 NM 手前から DES NOW にすると、30 NM 先が 45,250 ft、目的地は約 13 分早く出る（`B747.68.pred_model.lua:600-673`）。
- **ELEC UTIL BUS L/R と UTIL OFF の灯が、スイッチだけで決まる**【確認済み】
  - FCOM では、母線が電源を失ったときも出る（load shed 中は出さない）（`B747.03.elec_model.lua:553, 588`）。
- **電源の状態が、フライト開始で元に戻らない**【確認済み】
  - 電池の残り、GCR のトリップなどが残る（`B747.03.xt.elec_buses.lua:73`）。電池だけの C&D で終えると、次のフライトの電池が空のまま始まる。
- **油圧の作動油量が 0 で止まらず、漏れてもデマンドポンプが圧を保つ**【確認済み】
  - 量の表示はマイナスになる（`B747.19.hyd_model.lua:279`）。試験はこの振る舞いを正としている。
- **エンジン運転中で始めても、デマンドポンプやパックが OFF になりうる**【担当】
  - 原因：開始の形を、XTLua が 0 を返す最初の読み取りで判定している（`B747.20.xt.hydraulics.lua:372-380`、`B747.55.xt.air.lua:509-517` ほか）。
  - PROGRESS にある「X-Plane を起動して最初のフライトは、エンジン運転中を選んでも C&D で始まる」と合う。
- **経路が X-Plane の FMS の 100 行を超えると、同期が止まったままになる**【担当】
  - 長い SimBrief の洋上ルートで、AFDS や ND の PLAN が見る現在の地点が古いままになる（`B747.68.route_model.lua:1306-1309`、`B747.68.xt.fms.lua:2664`）。
- **安定板トリムの「外からの変更」の判定が、自分の書き込みの遅れを外からの変更と取り違えうる**【担当】
  - 起きうること：速い速度でトリムが動いているとき、モデルが巻き戻され、speed trim が外れる（`B747.45.xt.srm.lua:230-246`）。
- **ND の WPT のウェイポイントが、Navigraph ではなく既定の航法データから取られ、数分遅れて更新される**【担当】
  - （`B747.61.xt.nd.lua:1210-1265`）
- **エンジンのモジュールの、オートパイロットの dataref への書き込みが効いていない**【担当】

## 4. 小さなもの（低）

- A/T：THR スイッチの条件が FCOM p.642 の表と一部違う。推力の基準が 0 のとき、レバーを後ろへ動かす。古い VNAV のコードが降下中に書き込みを続ける。AFDS の入力を 1 フレームに 3〜4 回作る。
- VNAV：飛べない段階上昇を 1 分ごとに入れ直す。T/D の減速のキャッシュが重さを見ない。CRZ ALT = MAX で経路ごと消える。SPD TRANS が 250 kt の固定。DES ページの SPD TRANS が消せない。巡航上昇中に CRZ ALT を下げたときの降下の判定。
- オートブレーキ：油圧を失ったときに解除しない（ATA に従っている。FCOM は即解除）。
- 脚・操縦：ブレーキ温度が最初 0 ℃ から始まる。CONFIG GEAR のラッチがフライト開始で戻らない。FCU の脚の判定が翼の脚を見ない。
- 照明・火災：配列の範囲外の読み（元の機体）。煙排出のハンドルが戻らない。表示の明るさが一瞬 1 を超える。>STBY POWER OFF を出す所が無い（FCOM の確認待ち）。
- ACARS：INITIALIZE のページが空になる（元の機体）。WEATHER ページの ATC 欄の誤入力で ATC COMM が切れる。メッセージのページが違う番号で開く。
- 表示：F/O の TCAS の記号が機長の航跡を使う。Va の閾値の打ち間違い（未使用）。
- 試験の仕組み：シムの一時停止を「X-Plane が止まった」と判定する。配列の dataref を添字なしで比べると「どれか 1 つ」で合格になる。
- その他：simconfig で F/O の内側表示の設定が機長の値を読む。旋回の計算のキャッシュが風速の生の値で外れる。報告のページが文脈を何度も作り直す。

## 5. 問題なしと確かめたもの（抜粋）

- **FCOM と一致**：チラー 70°・ペダル 7°、RTO・オートブレーキ、>SPEEDBRAKES EXT、フラップのロードリリーフ、IRS の整列、高度警報、DISAGREE の閾値、A/T の TO/GA・FLCH・HOLD、APU（FCOM 7.30・7.40）、燃料（12.20）、AUTOSTART（p.879）、油圧のデマンドポンプの論理、パックの流量の段取り、CDU のスクラッチパッドの規則。
- **モデルの中身**：LNAV・経路のモデル（待機のエントリーの扇形、racetrack、procedure turn）、予測と性能の表、表示のモデルにも誤りは見つからなかった。予測の計算は 1 回 2〜3 ミリ秒で、重さの原因ではない。
- **プラグインとローダー**：C のプラグインはメモリの範囲・SimBrief のスレッド・SDK の後始末とも健全。今日のローダーの計時の包み（固まりの記録）は、動きを変えていない。

## 6. 直す順番の提案

1. **すぐ**：1 の止まる不具合 3 件（P&W の CRZ は誤報）。
   - CG の件は、今日の機能が踏みやすくしたので最初。重量が無ければ TRIM を空欄にする。
   - P&W の CRZ は誤報なので、CRZ を通る試験だけ足す。
   - PAX は、ループの終わりの条件を直す。
   - ND のファイルは、nil を確かめて Custom Data を先に開く。
   - それぞれに試験を足す。
2. **固まる件**
   - 確実に軽くできるものを先に：POS INIT のファイル読みを 1 回に、毎フレームのゴミ集めをやめる、FMC の JSON 化を変わったときだけに。
   - 残りの候補（CIFP の一括解読、格子、FMS への読み込み、ND の線）は、利用者の PC の記録を見て決める。
3. **3 の動きの誤り**：持ち越し・初回の読み取りの系統（A/T、電源、開始の形）、FCOM と違う論理（A/T の 400 ft、ELEC UTIL BUS）、予測（DES NOW）、油圧の量、100 行の同期の順。
4. **4 の小さなもの**：まとめて。
